# Diagnostics and Artifacts

Use diagnostics to answer a specific unresolved question, not to collect everything by default.

## Screenshots

- Capture both desktop and mobile for layout changes. Include the relevant state, not only the empty page.
- Inspect text wrapping, focus indicators, modal bounds, scrolling, media loading, and whether controls remain reachable.
- Check overflow on meaningful containers. Intentional horizontal scrolling inside code blocks is not page overflow.
- Use the ignored `frontend/artifacts/ui/` directory for AIChat screenshots. Do not commit generated screenshots unless requested.

## Traces and Video

- Start tracing after creating the browser context and before the failing action. Stop it to a specific artifact path before closing the context.
- Enable screenshots, snapshots, or source capture only if needed; traces may contain request headers, input values, page content, and source code.
- Configure video recording when creating the context. Close the context to flush recording before inspecting the file.
- For CLI diagnostics, verify installed command support and start a named browser session first. Do not assume trace output format or flags from another version.

## Logs and Cleanup

- Separate JavaScript exceptions from expected mocked HTTP failures. Keep the expected-failure case explicit in the test.
- Redact authentication headers, tokens, user messages, and private media before presenting diagnostic output.
- Report artifact paths, not large raw snapshots or complete network logs.
- Remove only artifacts generated by this task when cleanup is necessary. Do not recursively remove shared trace directories or other sessions.
- If a browser/runtime cannot be installed or a real backend is unavailable, state the blocker and the exact checks that remain unverified.
